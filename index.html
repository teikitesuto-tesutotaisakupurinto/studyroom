``` ## Firebase側で必要な設定 ### 1. Realtime Database のルール Firebase Console → **Realtime Database → ルール** を開き、次のルールに置き換えて「公開」してください。 ```json { "rules": { ".read": false, ".write": false, "rooms": { "main": { ".read": "auth != null", "players": { "$uid": { ".write": "auth != null && auth.uid === $uid" } }, "calls": { ".write": "auth != null" } } } } } ``` これは動作確認用のルールです。匿名認証した利用者なら、同じルームの参加者データと通話シグナリング情報を読めます。一般公開するサービスにする場合は、アクセス制御をさらに強化してください。 ### 2. 動作確認の順番 1. HTMLをHTTPSで開き、名前を入力して入室する。 2. Firebase Console の `rooms/main/players` に自分のデータが追加されるか確認する。 3. 別のブラウザまたは別端末から入室し、参加者一覧と位置が同期するか確認する。 4. 両方の端末で「マイク・カメラを開始」を押し、ブラウザの権限を許可する。 **注意：** このコードは参加者一覧・位置同期を先に確認できるようにし、音声・映像はWebRTCで接続する構成です。ただし、現在のコードでは、通話開始のタイミングによっては後から参加した側の音声・映像トラックを追加するための再ネゴシエーションが必要になる場合があります。また、STUNだけでは接続できないネットワークもあり、その場合はTURNサーバーが必要です。音声・映像まであらゆるネットワークで確実に動かすには、TURNを含む接続構成も必要です。
